Common divergences:
- `'a mltl_ext` is the mltl-core parse tree with `Seq<usize>` data
  (`MltlExt<A>`, D39). Temporal nodes carry the composition; other nodes
  carry data the algorithm never reads, so every theorem holds for any data
  there (stronger than Isabelle). Nodes the algorithm creates get `[]`.
  Isabelle's `F_c [a,b] <L> φ` is `MltlParseTree::Future(L, a, b, φ)`
  (data first); spec constructors `future_mltl_ext(a, b, L, φ)` etc. keep
  Isabelle's argument order.
- Compositions are `Seq<usize>` (Isabelle `nat list`); `b - a` is
  `nat_sub`. Positions from `interval_times` are `nat` and are cast to
  `usize` bounds (`s!i as usize`); for valid compositions all are `≤ b`
  (`blocks.rs : blocks_ok`, `block_bounds`), so the casts are exact.
- Sets of traces (`language_mltl_r`, `⋃`, `∩`, `{}`) are `ISet`.
- `x ∈ set D` → `D.contains(x)`; `∃ψ ∈ set D. π ⊨ ψ` → `lists.rs : sat_some`.
- Exec follows D20 (`<name>_spec` + exec `<name>`) on
  `MltlExtExec = MltlParseTree<usize, Vec<usize>>`, read by `exec.rs : ext_view`.
- Proofs: union and disjointness are each one induction on `k` whose
  operator cases combine a *lifting* lemma (`blocks.rs : *_list_sat`) with a
  *partition* lemma (`future/until/release_partition`,
  `*_blocks_exclusive`). Isabelle's ~3800 lines of case analysis for these
  have no line-by-line counterpart.
