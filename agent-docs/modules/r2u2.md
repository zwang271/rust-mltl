## Design decisions (owner review asked; D48)
1. **Queue = full history.** `Scq.all_values` is every write;
   `scq_entries = compact(all_values)` is what an unbounded ring would hold
   (compaction = overwrite the last entry when the value repeats). Reads
   return the first compacted entry with time ≥ the reader's `next_time`.
   Ring layer later: show the ring holds a suffix of `compact(all_values)`
   and returns the same reads when its capacity suffices.
2. **Meaning of a stream: `value_at(h, j)`** = value of the first entry with
   time ≥ j. Proofs work with it; `deaggregate` (Isabelle) is related once
   by `lemma_deaggregate`.
3. **Semantic invariant per node** (`soundness.rs : hist_inv`): strictly
   increasing, all times < b (steps read so far), and `hist_sound`: every
   covered step j has `value_at(h, j) = semantics(drop π j, φ_node)` for the
   **whole** trace π. Since the monitor read only `π[0..b)`, this says the
   verdicts are right for every extension. This is the property parents
   need from children; Isabelle states it only at the root, via
   `deaggregate (all_values)`.
4. **Formula = parse tree** (`MltlParseTree<A, NodeData>` from mltl-core),
   operators as in Isabelle's r2u2 form (Prop/True/False/Not/And/Until via
   `convert_r2u2_form`). Native OR/RELEASE (as in Rust R2U2): not now;
   revisit if UNTIL-only makes proofs or memory worse.
5. **Bounded reloop.** `repeat_mltl_update` has fuel
   `size·(n+1)+1`; soundness holds for any fuel, completeness shows fuel
   isn't hit. Avoids Isabelle's `r2u2_measure` termination proof.
6. **`Option` instead of `Undecided`.** Removes the `undecidedV = <Undecided, 0>`
   sentinel and the "undecided only at time 0" side conditions.

## Proof structure
`lemma_hist_push` (append a correct verdict right after the covered steps)
→ `lemma_load_step`, `lemma_not_step` (operator level; NOT also proves the
completeness and "no change" cases) → `lemma_update_first` (first pass of
step n: invariant `b = n` → `n+1`), `lemma_update_reloop` (later passes
keep `b = n+1`; on a complete tree they change nothing and report no
progress) → `lemma_repeat`, `lemma_engine_step`, `lemma_run` →
`r2u2_run_correct`, `r2u2_correct_load_not`.
`tree_inv` per node kind: leaves have covered exactly `[0, b)`; NOT nodes
have `next_time = next_after(own history)`. `tree_complete`: every node
covers `[0, b)`.

## AND (done 2026-10-04)
Same invariant as NOT (`next_time = next_after(own history)`).
`lemma_and_step` handles all cases at once: the written verdict `v` is the
last element of the new history, and for each `j ∈ [next_time, v.time]`
whichever child read covers `j` decides. Completeness needs both children
complete; then both reads return the step `b − 1` entries, so one pass
suffices in this fragment. Proof pitfall: in `lemma_update_reloop` the
"complete ⟹ unchanged" case needs `assert(tree_complete(*c, n + 1))`
before facts about the child's history (two unfoldings of `tree_complete`).

## UNTIL (done 2026-10-04: soundness)
`until.rs`. For `φ U[a,b] ψ`, `P = next_after(own history)` (first
unwritten output), `τ = next_time` (first unread child time). `until_inv`:
bounds in the observer equal the tree's `a ≤ b`; `prev_verdict` = last
written; `P + a ≤ τ ≤ P + b`; gap: every child time in `[P + a, τ)` has ψ
false and φ true. Branches (`lemma_until_branch_*`):
- ψ true on `[τ, t_r]` → `<T, t_r − a>`; witness for output `i` is
  `max(i + a, τ)` (≤ `i + b` by `τ ≤ P + b`; φ on the gap).
- ψ false, φ false on `[τ, t_l]` → `<F, t_min − a>`; any later ψ-witness
  has a φ-failure at `max(i + a, τ)` before it.
- ψ false on `[τ, t_r]`, `t_r ≥ P + b` → `<F, t_r − b>` (whole window ψ-false);
  `next_time = max(x, P' + a)` with `x = t_min + 1` (φ true read) or `τ`.
- φ true, window open → `next_time = t_min + 1`, gap grows.
Mutations (each → 1 error, 2026-10-04): true/left-false written one step
too far; elapsed test `prev + ub` (pre-fix `>`), first window `ub − 1`;
wait skipping an unread step; elapsed/no-left `next_time + 1` (Isabelle's
older commented version); elapsed/left without `max`; true branch
`next_time = t_r + 2`.

## Promptness (done 2026-10-04, D49)
`promptness.rs`. Definition agreed with the owner: deadline `t + wpd(φ)`
(Isabelle `wpd`: U adds `b`), not Isabelle's progression-based
`r2u2_promptness` (too eager; false for R2U2).
- Termination: `tree_measure` = Σ over nodes of `(n+1) − written-up-to` +
  `(n+1) − next_time` (nat_sub). A reloop pass reporting progress wrote
  something, so the measure drops (`lemma_update_measure`; per-op
  `scq_step_ok`); `step_fuel = 2·size·(n+1)+1` exceeds the measure after the
  first pass (`lemma_tree_measure_bound`). So the step ends with a pass
  reporting no progress (`lemma_repeat_prompt`).
- Last pass (`lemma_last_pass`): it writes nothing. NOT: read nothing ⇒
  `next_time ≥ child coverage`. AND: one side read nothing. UNTIL: if
  `next_time < g = (n+1) − wpd(operands)` both children (prompt by
  induction) have data, the only non-writing branch is the skip, which
  raises `next_time` by ≥ 1; and `untils_ready` (from the previous step)
  says `next_time ≥ g − 1`. So `next_time ≥ g`, and `P ≥ next_time − b` by
  `until_inv`.
- **The skip reports no progress in Isabelle/Rust and the proof works
  anyway**: the argument only needs "the last pass writes nothing".
- Mutations (2026-10-04, each 1–2 errors): skip not advancing `next_time`;
  no reloop passes; `wpd` one smaller for U; fuel = size.
- Found on the way (spike `../verification/spikes/r2u2-promptness/`):
  reporting progress on the skip makes some verdicts come out earlier (up to
  12 steps of coverage at inner nodes in random tests), never later; real
  Rust `r2u2_core` timing equals the faithful model in 43/43 compared runs.
  Latency, not correctness. Invariant discovered there: `next_time ≥
  min(cov_l, cov_r, (n+1) − wpd(operands))` at the end of every step
  (3.4M node-steps, 0 violations); `P + b ≥ min(cov_l, cov_r)` alone fails.

## Queue sizes (done 2026-10-04)
`queue_size.rs`. `backlog(child, τ)` = compacted entries at or after the
reader's `next_time`; ≤ `nat_sub(cov, τ)` (`lemma_backlog_bound`: distinct
times). `nodes_ready(t, k)`: every reading node has `next_time ≥ k −
wpd(operands)` (NOT/AND via `tree_prompt`, UNTIL via `untils_ready`). In
step `n`, cov ≤ n + 1 ⇒ backlog ≤ wpd(operands) + 1 (`lemma_reads_fit`),
for every pass of the run (`run_reads_fit`, `r2u2_queue_sizes`). Mutation:
size `wpd(operands)` (no `+1`) → 1 error.

### Candidate #5 is wrong (2026-10-05)
Counterexample (`cex5.py`): `((((p1 U[3,7] p0) & (p1 U[1,3] p1)) U[1,5] p0) & p0)`
on the 9-step trace `{p0}, {p0,p1}, {p0,p1}, {p1}, {p0}, {}, {p0,p1}, {}, {p0}`. #5 gives the slow child
(the `U[1,5]`, wpd 12, bpd 1, sibling `p0` wpd 0) 2 slots; at step 6 it
reports true, the unbounded model (= #4) false. Found by `min5.py` once
intervals and traces were varied (`stress5.py`, `one5.py`: on
`(p1 & (((p0 U[16,28] p0) U[18,35] (p0 U[10,23] p1)) & !(!(p0))))` #5 is
wrong on 668/3000 traces, `&`+2/`U`+3 on 95, #4 on 0). Mechanism (`probe9*.py`):
when the reader is behind its fast sibling (`τ < cov_s`) the slow child's
backlog over the sibling term grows with interval sizes (seen 2 at
bounds ≤ 8, 3–4 at bounds ≤ 40): the reader chews through the sibling's
entries one per pass while the slow child keeps writing. With `τ ≥ cov_s`
the backlog is always ≤ the sibling term. Lesson: random tests with small
intervals (`rf(3, 4)`) are not evidence for size rules; stress with large
intervals and long traces.

### Candidate #5: why it is harder than #4 (spike 2026-10-04)
- #5 differs from #4 only when the child is the **slower** one by more than
  `k`: `wpd(c) > wpd(s) + k` (then `wpd(s) + 1 + k − bpd(c) < w + 1 − bpd(c)`).
  (An earlier explanation to the owner said "faster child"; that was wrong.)
- #4's proof bounds the backlog by a *time* gap (`lemma_backlog_bound`:
  entries ≤ `cov_c − τ`). For #5 that gap is unbounded relative to the
  sibling term: `probe6.py` sees `cov_c − τ` exceed `max(wpd(s) − bpd(c), 0)`
  by up to 9 (a slow child jumps its coverage with one entry). The *entry*
  backlog stays small: `probe5.py`, excess over the sibling term ≤ 2 for both
  `&` and `U` readers (≤ 1 in the first pass for `&`) — at interval bounds ≤ 8 only; it grows with larger intervals (section above).
- So #5 needs an entry-counting argument across passes, not a time bound:
  nodes add up to 6 (`&`) / 5 (`U`) compacted entries in one step
  (`probe7.py`), so "few writes per step" is false; what keeps the backlog
  small is that the reader consumes in between. End of step,
  `next_time ≥ min(cov_l, cov_r)` holds for every `&` (0 / 279k) but not for
  `U` (125 / 1.1M violations; `U` needs the `(n+1) − w` term).

## Our sizes vs C2PO/Isabelle (2026-10-04)
Notation, for a node `N` with children `l`, `r` (reader `N`, child `c`):
`w = wpd(operands of N) = max(wpd l, wpd r)`; `bpd(c)`, `wpd(c)` as in
`engine.rs`.

- C2PO `passes.py : compute_scq_sizes` = Isabelle `queue_size_sibling_nodes`:
  size of `c` = `max(wpd(sibling of c) − bpd(c), 0) + 1`; NOT child, root: 1.
- Ours, first version (D48): size of `c` = `w + 1`, uniform over the
  children. Always ≥ C2PO per node (uses the *max* of both children's wpd,
  not just the sibling's, and no `bpd`).
- Ours, current (2026-10-04): size of `c` = `max(w − bpd(c), 0) + 1` for a
  child of AND/UNTIL, 1 for a child of NOT, 1 for the root. Keeps the `max`
  (that is what the proof needs — see below) but subtracts the child's own
  `bpd`, which is where almost all of the slack was.

Spike `sizes.py` / `sizes2.py` (20k random formulas, depth 4, traces of 30):

| rule | wrong runs | total slots |
|---|---|---|
| C2PO / Isabelle (sibling) | 80 / 20000 (value errors) | 1.00× |
| sibling + 1 | 1 / 20000 | 1.42× |
| sibling + 2 | 0 / 20000 | 1.85× |
| ours, `w + 1` (superseded) | 0 (proved) | 1.56× |
| ours, `max(w − bpd(c), 0) + 1` | 0 (proved) | 1.24× |

Why C2PO's rule is too small: it bounds only the *skew between siblings*,
not how far the **reader** itself can lag behind a child. A reader's
`next_time` is only guaranteed to be at `n − w` (promptness), so it may need
entries the child wrote over the whole window `[n − w, (n+1) − bpd(c))`,
which has `w + 1 − bpd(c)` steps — our rule. Using the sibling's `wpd`
instead of the max drops the reader's own delay from that window.

## Sizing experiment: how much of our extra is needed (2026-10-05)
(Outcome: the "half" rule, now proved — next section.)
Spike `../verification/spikes/r2u2-sizing/` (README there has method,
commands, numbers). Notation: child `c`, sibling `s`, `x + 1` = ours,
`y + 1` = C2PO (`y = max(wpd(s) − bpd(c), 0)`); they differ only when `c`
is the slower child.
- Per-queue need is measured exactly from one unbounded run (rule in the
  spike README, checked against real rings). Model with C2PO sizes = real
  `r2u2_core` (`--no-rewrite --no-cse`) on 40/40 wrong-value cases, outputs
  identical.
- Every C2PO shortfall (54k queues) is at a slower child; 98% have C2PO
  size 1. C2PO-correct formulas: ours 1.18–1.37× C2PO.
- Mechanism (`explain` logs): slow child catches up with one long entry; the
  reader walks it ~1 step per pass with ~2 passes per step (UNTIL skip
  reports no progress), the child adds 1 entry per step meanwhile.
- **Candidate "half": `y + ⌈(x − y)/2⌉ + 1`.** (VERIFIED since, see below.) Never
  beaten (grids 884k edges; targeted `stress` 10.8k formulas × 4k iters,
  2k × 40k iters), reached exactly on thousands of edges; `⌊⌋` instead of
  `⌈⌉` is beaten. ≈ 1.19× C2PO total vs ours 1.38×. Proof idea: rate
  argument in `ptr_inv` (≥ 2 passes per step, ≥ 1 step consumed per read
  with data) instead of the time bound `τ ≥ n + 1 − w`. Lesson from #5
  applied: large intervals (≤ 40), long traces, one atom per leaf.

## Half-size queues (done 2026-10-05, `half.rs`, D55)
Only a slower child (`x > y`) needs the new argument; otherwise
`⌈(x + y)/2⌉ = x` and the time bound of `ring_sim.rs` applies.
- Potential `psi(c, τ, cap)` = `wsum` (steps left in the reader's current
  entry `k`, plus `tail_w`: every later entry its gap but at least 2) +
  `nat_sub(cap, max(cov, τ))`. Lemmas: `lemma_psi_write` (child write: +1 at
  most, only if `ent > 0`; cases push/merge × reader has data or not),
  `lemma_psi_move` (reader moves: −1 at least, or 0), `lemma_psi_cap`
  (+1 per step), `lemma_psi_bounds` (`ent > 0`: `psi ≥ 2·ent − 1 +
  headroom` and `psi ≤ 2·(cap − τ) − 1`).
- Invariant `half_inv(t, n + 1)` before every pass of step `n`, per edge
  `edge_ok`: `x > y ⇒ psi ≤ x + y + [ent = 0]`. Kept by every pass
  (`lemma_update_half`): the reader moved, or had no data from `c`, or none
  from the sibling (`lemma_stay`; then `τ ≥ cov_s ≥ n − wpd(s)` and
  `psi ≤ 2y + 1 ≤ x + y`). After the last pass (`lemma_last_half`, needs
  `nodes_ready(n + 1)` and `tree_prompt(n + 1)`) it holds for `n + 2`.
- Ring: `room(c, τ, w, cap)` (`ent ≤ w`, or `w + 1` with the child at
  `cap`) replaces `τ ≥ cap − (w + 1)` in `lemma_ptr_after_read` /
  `lemma_child_read`; `lemma_child_rooms` gives room (potential for `x > y`,
  time bound `lemma_room_time` otherwise). `sim_ok`'s next-step clause is
  now conditioned on `last_cond` (no progress + `nodes_ready(n + 1)`), since
  the potential needs "nothing written in the last pass". `hist_pre` carries
  `half_inv`; `lemma_sim_repeat/step/run` thread it; `lemma_initial_half`.
- `init_ex` needed `spinoff_prover` + `rlimit(100)`; `lemma_update_half_until`,
  `lemma_last_half_*` `rlimit(100)`.
- Spike check of the exact invariant first (7.5 billion pass checks, 0
  failures, `CHECKINV=1 bin/v6 psi …`) saved guessing in Verus.

## Ring layer (done 2026-10-04)
- Operators were split into `*_core(parent, reads…)` + history wrappers
  (`not_op = not_core(parent, scq_read(..))`, etc.), so both storage models
  share one operator definition.
- `ring.rs`: `Ring { slots: Seq<Option<Verdict>>, write_ptr }`,
  `ring_write` (Isabelle `scq_write`: overwrite previous slot if same value,
  else write and advance), `ring_scan`/`ring_read` (Isabelle
  `scq_read_aux`: scan from the pointer, return first entry ≥ τ, stop before
  the write pointer leaving the pointer on the last slot). `ring_abs`: entry
  `i` of `compact(all_values)` is in slot `i mod N` for the last `N`
  entries, `write_ptr = len mod N`, unused slots empty — the exact
  ring↔history link Isabelle's `valid_scq` lacks. `lemma_ring_write`,
  `lemma_ring_read` (pointer at logical `j ≤ first_idx`, `len − j ≤ N`).
- **Stale pointers / tight size (`+1`, 2026-10-04).** A reader's pointer
  stays where its last read stopped; it can be up to `w + 2` entries behind
  the end (`w = wpd(operands)`; measured). With `w + 1` slots its slot does
  get overwritten (~7% of reads), but only by the entry the reader needs.
  Proof (`ptr_room`, `ptr_at`, `ptr_inv` with `m` = steps read): before each
  pass of step `n` the pointer is at most `w` from the end, or `w + 1` with
  the child's coverage at `n + 1` (no new entry possible this step), or at
  the last entry with nothing stored still needed. A read leaves it at the
  first needed entry (backlog ≤ `w + 1`, ≤ `w` if the read is at `(n+1) −
  w`) or the last. `queue_size.rs : lemma_last_ready`: before the last pass
  of a step (no progress) every reader is `nodes_ready(·, n + 1)`, using
  `until_c` (after any pass, an UNTIL with data on both sides is at
  `(n+1) − w`: with both reads `Some` it moves; `lemma_update_c`) and
  `lemma_rlnp_root`. Hence after a step every pointer is ≤ `w` from the end
  (`rtree_inv(·, ·, n + 2)`), and the first pass of the next step adds at
  most one entry. `lemma_ptr_read_pos` handles the one-slot case (the slot
  holds the new entry, the only one needed). Mutations: child size
  `wpd + 0` → 1 error; dropping `lemma_last_ready` → 1 error. (Still the
  argument in force; "Tighter per-child sizes" below only replaces `w` by
  `w_c` and `n + 1` by the child's `cap`.)
- Earlier versions: `+3` (pointer low-time invariant), then `+2` (≤ 1 child
  write between reads). Superseded.
- `ring_engine.rs`: `RNode` (ring, ghost `all_values`, `next_time`,
  `rd_left/rd_right`, observer), `mltl_update_r` etc. mirror the engine.
  `ring_sim.rs`: `lemma_sim_update` (one pass: `abs_tree` commutes, same
  progress, `rtree_inv` kept) split per node kind (`lemma_sim_{leaf,not,and,
  until}`; two need `#[verifier::rlimit(100)]` + `spinoff_prover`), then
  `lemma_sim_repeat/step/run`, `r2u2_ring_eq`, `r2u2_ring_correct`.
- Mutations (each 1 error, on the `+3` version): ring write without
  compaction; read leaving the pointer past the write pointer.
- Tightness (spike `ringsim.py`, `ptrcond.py`, 20k random runs each):
  `+1/+2/+3` match the unbounded output; `max(1, wpd)` fails 1093;

## Tighter per-child sizes (done 2026-10-04, `tight.rs`)
The uniform `w + 1` was loosened to per-child `w_c + 1` with
`w_c = max(w − bpd(c), 0)` (NOT child: 1). Two new history-level facts, both
proved by induction over passes/steps and threaded through `hist_pre`:

- `cov_ub(t, b)`: after `b` steps have been read, every node has covered at
  most `b − bpd(φ_node)`. Each operator writes a verdict at least its lower
  bound behind what it read (`lemma_not/and/until_write_ub`; UNTIL needs
  `parent.next_time ≥ lb` and `lb ≤ ub`); `lemma_cov_ub_root` +
  `lemma_update_cov_ub`. Note the bound is `nat_sub(b, bpd)`, not `b + bpd`:
  a slow node is *behind*.
- `not_caught(t)`: every NOT node's `next_time` is already at or past
  everything its child wrote. True initially, and preserved
  (`lemma_not_catch_up`): NOT reads *after* its child's pass, so if the read
  returns anything it is the child's newest entry and NOT jumps to
  `cov + 1`; if it returns nothing the new entry was already before `τ`.

The pointer invariant is the same shape, parameterized: `ptr_inv(rd, child,
τ, w_c, cap)` with `cap = nat_sub(m, bpd(φ_c))` instead of `m = n + 1`.
`lemma_ptr_read_pos`/`lemma_ptr_after_read` take `cap` and need
`τ ≥ nat_sub(cap, w_c + 1)`, which follows from `τ ≥ nat_sub(n, w)`
(promptness) by `lemma_cap_slack`: `(k − b) − (w − b + 1) ≤ k − (w + 1)`.
NOT children use a separate branch, `lemma_ptr_after_read_caught` /
`lemma_child_read_caught`: with `not_caught` the pointer always ends on the
child's last entry and `first_idx(c, τ2) = |c|`, so the third `ptr_room`
disjunct holds for **every** `m` and one slot is enough regardless of how
far behind the child is.

Mutation (2026-10-04): `child_slack = nat_sub(w, bpd(c) + 1)` (one slot
fewer wherever `bpd(c) < w`) → 5 errors, including
`tau >= nat_sub(cap, w + 1)` in `lemma_child_read`.
